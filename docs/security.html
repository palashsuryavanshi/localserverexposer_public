Privacy and security

What the app does with your data, what sharing a local server means, and what it does to reduce the risk.

Exposing a server makes it reachable from the public internet.

A Quick Tunnel URL is unguessable but bearer access: anyone who obtains it can send requests to your server until you stop the tunnel. Only share development servers you trust, on a machine you control, and stop tunnels when you are done.

The short version

  • The link is the credential — treat it like a password.
  • Only expose development servers you trust.
  • No telemetry, no analytics, no account system.
  • Tunnel URLs are redacted before anything is written to disk.
  • A tunnel cannot outlive the application.
  • The binaries are not code-signed; verify the published SHA-256.

What happens when you expose a server

Local Server Exposer starts a Cloudflare Quick Tunnel: your local port is bridged to an ephemeral public HTTPS URL on *.trycloudflare.com, served through Cloudflare's network.

  • The URL is bearer access. The hostname is random and hard to guess, but anyone who obtains the URL can reach your server for as long as the tunnel runs. Do not post it publicly.
  • Your server sees the real traffic. Requests arrive at your local process with their original path, headers and body. If your dev server has an unauthenticated admin endpoint, it is now on the public internet.
  • You stay responsible for what you share. The app does not filter content passing through the tunnel.
  • Cloudflare sees the traffic, as any reverse proxy must; their privacy terms apply.
  • Quick Tunnels are for development — anonymous, no custom hostname, not a production front end.

Stopping the tunnel ends it: the URL stops resolving to your machine as soon as the tunnel process exits.

What the application refuses to do

Confirmation before every exposureEvery start — including retries — shows a dialog naming the port and process. There is no permanent "don't ask again".
Only HTTP/HTTPS can be exposedThe app re-probes the target itself immediately before starting a tunnel and refuses anything that does not answer as a web server.
Only loopback targetsDiscovery and probing are limited to 127.0.0.0/8 and the 0.0.0.0 wildcard. Remote hosts are never probed or exposed.
Tunnels never outlive the appEach tunnel process belongs to a Windows Job Object that terminates its members when the app's process ends — including on crash, forced kill, sign-out or shutdown.
No shell executionProcess arguments are fixed and built in the backend; the interface has no shell, filesystem or process capability.
The tunnel client is verifiedChecked for plausible size, PE executable format and a parseable --version — before first use and before every tunnel.

Local data and logs

Everything the app stores lives in %APPDATA%\com.localexp.local-server-exposer\:

config.jsonUI preferences, favorite ports, scan interval, autostart flag. No credentials, no tunnel URLs.
logs\Daily rotating files with 7-day retention, plus panic.log on a crash. Tunnel URLs are redacted (https://[tunnel].trycloudflare.com) before anything is written. Response bodies, headers and cookies are never logged.
cloudflared.exeThe Cloudflare tunnel client, present only if you chose to install it, and verified before use.

There is no telemetry and no analytics: the app reports nothing to anyone.

Two honest caveats:

  • URL redaction is a filter applied to text the tunnel client prints; it is not a guarantee about every future version of that output.
  • Windows toast notifications stay in the Windows notification history until dismissed, and a tunnel notification includes the public URL. Clear notification history on shared machines if that matters.

Downloads

The tunnel client (cloudflared) is downloaded only when you explicitly approve it, from the official Cloudflare release URL over HTTPS. It is never bundled with the installer, and a valid copy is never silently replaced. cloudflared is © Cloudflare, Inc. and is licensed under the Apache License 2.0.

Integrity of the binaries

Every release publishes a SHA256SUMS.txt, and a workflow recomputes each checksum after publication. For 1.0.0: 

f9c5b14266ea4ca4f337bc07053c6e3a160ead384286a82e75ecbc01a00c12a4  LocalServerExposer_1.0.0_x64-setup.exe

The binaries are not Authenticode-signed, which means SmartScreen shows an "unrecognized app" warning and the app has no publisher reputation. Authenticity therefore rests on the published checksum, not on a signature chain. Download only from the releases page.

Threat model summary

Accidental exposureMitigated: confirmation per exposure, honest status labels, destructive actions separated.
Exposing a non-web serviceNot possible: re-validated in the backend before each start.
Malicious response from a probed serverMitigated: probing is bounded (size caps, timeouts, header and title limits) and nothing is rendered as markup.
Command injection via port, path or URLNot possible: typed arguments, integer ports, strict URL validation, no shell.
Compromise via the tunnel clientMitigated: HTTPS download, size + format + --version verification, re-verified on every use.
Orphaned tunnel after a crashNot possible: kill-on-close Job Object, covered by automated tests.
Public URL leaking through logsMitigated: redaction before writing; residual risk from notification history.

Known limitations

  • Tunnel URLs are bearer credentials. Inherent to the product.
  • No checksum pinning for the tunnel client. Cloudflare publishes no checksum file at the download URL used, so identity rests on HTTPS, format and --version.
  • Self-signed HTTPS origins are reached with TLS verification relaxed, and only for loopback targets.
  • Unsigned binaries mean no publisher reputation and a SmartScreen warning.
  • Notification history retains tunnel URLs until cleared.
  • This application has had an internal threat-model review. It has not been penetration tested or certified by any third party, and no malware-free status is claimed.

Reporting a security issue

Report privately through GitHub Security Advisories for this project rather than in a public issue, and give the maintainer a reasonable time to release a fix before disclosing details.

Never include a live tunnel URL in a report. Treat it as a password.
