Troubleshooting

The problems people hit most often, and what actually causes them.

Discovery

No servers are listed

Confirm your dev server is bound to 127.0.0.1 — some tools bind to a LAN address instead — then press Refresh. Discovery reads loopback and wildcard-bound IPv4 listeners only.

A port shows Unsupported

It is listening but does not answer as HTTP or HTTPS. Databases, debug protocols and raw TCP services land here by design: the application will not offer to expose something it cannot identify as a web service.

A port shows Unreachable or Unknown

The socket was listed but did not answer the probe. Typical causes: a firewalled port, a socket closing mid-scan, or a process owned by an administrator-level account whose identity Windows does not disclose to a normal user.

A server keeps disappearing

Short-lived processes do that — a dev server restarting, a test fixture exiting. Cards for servers that vanish while tunneled stay visible as unavailable, so you can still stop the tunnel.

Tunnels

Expose is unavailable

Only cards marked Ready can be exposed. Anything else is either not an HTTP service or was not reachable at scan time.

“cloudflared is not installed yet”

The tunnel client is downloaded on demand and never bundled. Use Install cloudflared on the Tunnels page (this needs internet), or point Settings → cloudflared executable at an existing copy. Whatever you supply is verified before every tunnel starts, so a wrong or corrupted file is refused rather than executed.

The tunnel stays on Starting

Registration normally completes within seconds. If nothing is published after about a minute the app stops waiting and reports the failure. Usual causes: no connectivity, a captive portal, a proxy or VPN that blocks the connection, or Cloudflare being unreachable from your network.

The tunnel says Tunnel failed

The card carries the reason. Common ones: the connection dropped during registration, the tunnel client was replaced or deleted while running, or Cloudflare refused the connection. Press Retry after fixing the cause.

My public URL stopped working

Check whether the tunnel still shows Exposed. If it stopped, start a new one — each tunnel gets a fresh URL; the previous address is not reused.

What happens on crash or sign-out?

Tunnels are attached to a Windows Job Object, so the operating system terminates them when the application process ends. A public URL cannot keep serving without the app.

The application

Blank window, or nothing opens

Install or repair the Microsoft Edge WebView2 runtime, then relaunch. Reinstall from the releases page if it persists.

Where did the window go?

Closing the window hides it to the tray while Minimize to tray is on. Use the tray icon, or turn the setting off.

Where are the logs?

Settings → Open logs folder opens %APPDATA%\com.localexp.local-server-exposer\logs\. Daily files are kept for seven days; tunnel URLs are redacted before anything is written.

Does it slow the machine down?

Idle CPU use is effectively zero and a scan costs a small fraction of one core, even with many listening ports. You can also lengthen the scan interval in Settings.

Windows and security

“Windows protected your PC”

Expected: the binaries are not code-signed, so they have no publisher reputation. Confirm you downloaded from the releases page, check the SHA-256 checksum, then choose More info → Run anyway. Do not disable SmartScreen permanently.

The installer asks for administrator rights

It should not — the installer is per-user. If you are prompted, something in your environment is rewriting the install; check with your administrator.

Uninstalling left my data behind

Intentional. Settings, favorites, logs and the downloaded tunnel client are kept so a reinstall keeps your preferences. Delete %APPDATA%\com.localexp.local-server-exposer\ to remove everything.

Still stuck?

Open an issue on GitHub with the application version, your Windows version, what you expected and what happened. Never paste a live tunnel URL — a URL is access to your server.
